# Spring Cloud

本模块关注多个独立服务协作后出现的问题。重点是理解问题模型，不把某个组件的配置方式当作永远不变的知识。

## 核心概念地图

- 服务拆分与边界
- 服务注册与发现
- 集中配置管理
- API 网关
- 服务调用与负载均衡
- 超时、重试、熔断与限流
- 日志关联、指标与链路追踪

## 推荐复习顺序

先确认为什么需要拆分服务，再学习服务发现、配置和网关；最后处理失败、流量与可观测性。每引入一个基础设施组件，都应能说明它解决的具体分布式问题。

## 快速自测

1. 单体应用在什么条件下才值得拆分？
2. 服务发现解决了哪一类地址管理问题？
3. 重试为什么可能放大故障？
4. 网关与服务内部鉴权的职责如何划分？
